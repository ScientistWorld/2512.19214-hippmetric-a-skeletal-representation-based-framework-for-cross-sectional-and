# Scientist Constraints

## Data

Use the dataset generated by `data/synthetic_hippocampus.py` with the default seed and dimensions for reported benchmark scores. Methods may read `data/synthetic_hippocampus.npz` only. Do not train on or directly read `data/synthetic_hippocampus_labels.npz`, `gt_thickness`, `gt_landmarks`, or procedural `transforms`; those arrays are evaluation labels only.

## Output Interface

Methods must write the same output fields consumed by `eval/evaluate_outputs.py`: `pred_thickness`, `pred_landmarks`, `recon_vertices`, and `valid_spoke_fraction`. The last field is a legacy metric name for local-measurement validity; the evaluator caps it by checking for finite, nonnegative thickness values and finite landmark/surface outputs. Evaluation must remain independent of `method/`.

## Resource Scale

Do not increase the procedural grid resolution, subject count, or timepoint count when reporting scores against this benchmark. The paper's claim is about geometric correspondence and valid morphometry, not resource scaling.

## Compliance Checklist

- [ ] Method code does not import from `eval/` or read ground-truth label arrays.
- [ ] Evaluation code does not import from `method/`.
- [ ] Benchmark generation uses the default script parameters.
- [ ] Scores are computed by `scripts/evaluate.sh` from method-produced artifacts.
